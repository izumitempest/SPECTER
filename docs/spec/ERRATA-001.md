# ERRATA-001 (applies to spec-v3.3; does not reopen the freeze)

**Status:** errata to the frozen patch spec. Merged alongside P-01…P-18 in the spec-v3.3 tag commit. Each item cites its patch ID per the freeze policy. Priority reflects proximity to claim-invalidation.

E-01 · [P-06] · HIGH — JPEG fill bytes. In entropy mode, on FF: peek next — 00 = stuffed literal (consume both); D0–D7 = restart (consume both); FF = fill (consume one, re-peek); else = real marker. Marker mode skips leading FF fill bytes before every marker code (FF FF FF D9 = EOI with two fills). Fixture: cjpeg output plus a hex-edited fill-byte variant; regression test required.

E-02 · [P-01] · HIGH — two-phase blob GC. Phase 1: BEGIN IMMEDIATE; delete rows with refcount = 0; COMMIT. Phase 2: BEGIN IMMEDIATE (used purely as a cross-process mutex — no DB writes, rollback cost zero); re-verify each row is still absent (a recreated row means a concurrent writer won — skip); unlink; COMMIT empty. Crash windows degrade only to orphan files (benign, collected by reconciliation). GC runs emit one summary audit entry (orphans removed, rows flagged lost) so the trail stays complete without per-blob noise.

E-03 · [P-03] · HIGH — pinned Merkle tree shape. Levels with an odd node count > 1 duplicate the final node (parent = SHA256(n‖n)); pairwise parents are SHA256(left‖right) over fixed-width 32-byte concatenations; a single leaf's root is the leaf hash itself. Pinning matters because the root is exported out-of-band — independent re-derivation (third parties, re-implementations, future versions) must compute identically. Fixtures: an image sized for an odd chunk count and a partial trailing chunk (one fixture exercises E-03 + P-03), plus a sub-chunk-size image (n = 1).

E-04 · [P-01/P-04c] · HIGH — commit-order reconciliation. Blob rows are cache state and carry no audit entries; P-04(c) co-commitment applies to audited transitions (artifact rows, job status). Worker flush batch = artifact rows + blob row inserts/updates + audit entries in one transaction; renames execute after commit (P-01's order, now unambiguous). Readers map blob ENOENT to lost semantics during the commit→rename window and mid-GC — never an unhandled error. Temp-prefixed files (crashed writers) are swept by age; they are never GC-eligible as content-addressed names.

E-05 · [P-11] · MEDIUM — regex clamp replaces rejection. Unbounded patterns (*, +, {n,}) are accepted, not rejected: evaluated with truncation-detection (a match ending exactly at the window boundary is re-evaluated against an extension buffer), hard-capped at 64 KiB default, with matches hitting the cap flagged truncated. Bounded patterns retain the computed-overlap path. The original rejection rationale (pathological matches are analytically useless) argues for clamping, not rejection — the review's practice claim was overstated, but clamp dominates rejection regardless. If AST max-length analysis is unavailable (re._parser is semi-internal), the pattern falls back to the clamp path. Property tests: unbounded patterns yield flagged results; boundary-spanning matches are found.

E-06 · [P-08] · MEDIUM — cursor execution model. "Global" means global across signature searches within one carve job, which executes as a single sequential scan (P-05's sequential windows) in one worker process; the cursor is that job's process-local state. Pool parallelism applies across jobs (different images, per the per-image lock) and within a job to chunk hashing and artifact triage — not to the scan loop, whose state is inherently sequential. If the P-09 gate ever demands parallel candidate validation, the escape hatch is dispatching candidates to the pool with the cursor advancing only past the header, and suppressing masked regions post-hoc — a design fork, not specced until the gate fails.

E-07 · [P-12] · MEDIUM — deployment constraint, normative. The reference deployment runs a single API process. Multi-worker Uvicorn/Gunicorn is out of scope for v1: it forks the in-process job pool, multiplies audit writers, and silently partitions the in-process rate limiter. If that topology is ever introduced, rate-limit counters move to SQLite and job orchestration is reworked — documented, not implemented.

E-08 · [P-17] · LOW — kill-test assertion wording. "Considering only committed rows: every Artifact/Job row present post-crash has its chain entry, and every entry's referenced row exists." Un-flushed batches vanish coherently per co-commitment — the test must not treat their absence as failure.

E-09 · [P-04] · LOW — seq semantics note. seq is commit order by design; the chain is a chronological log of committed transitions. Evidence spatial order lives in artifact offsets. Concurrent jobs on different images interleave in commit order — by design, not defect.

E-10 · [P-06] · LOW — cross-reference fix. JPEG entropy-mode profiling belongs to M1's clean-image throughput measurement, not the P-09 density gate (which measures the candidate path).

Register additions: A-C1's "irrecoverable loss" (refuted: re-carve backstop + lost flagging); A-C1's naive commit-then-unlink (rejected: reintroduces the round-4 GC-vs-writer race); A-C2's "architecturally invalid" (rejected: P-05 specifies sequential scan); A-C3's premise (rejected: deployment out of scope, constraint now normative); A-S2's "unusable" (overstated; clamp adopted).


E-01 + — Dangling FF: an entropy-mode scan ending on a trailing FF with no byte to peek (cap or image end) terminates via the fallback path — treated as no-EOI-found, low-confidence; never a marker parse. Fixture: truncated JPEG whose final byte is a literal FF.

E-02 + — (a) FS-mutation totality: all unlink/replace sites catch-and-skip on Windows PermissionError (handle open elsewhere) and POSIX ENOENT (already gone); skipped paths defer to the next pass; no exception propagates past the job boundary. Stated asymmetry for the writeup: POSIX unlink-while-open succeeds (the reader keeps a valid fd to an unlinked inode); Windows refuses — the trigger is deletion-during-read, per the correction above. (b) Phase-2 batch bound: ≤ 256 unlinks per phase-2 pass, remainder deferred — unbounded batches hold the writer mutex against concurrent flush batches, converting GC into a system-wide stall. (c) Phase-2 unlink ENOENT is a benign skip, not a failure.

E-04 + — (a) Retry-before-lost: ENOENT with the row present and status = active → bounded retry (5 × 20 ms) to ride out the commit→rename window; only persistent ENOENT reports lost. (b) Readers never repair: reader-side lost is an error surfaced to the caller; re-carve decisions belong exclusively to reconciliation/GC. (c) Temp-sweep rule: temp files carry the owning job ID (<job_id>_<uuid>.tmp); the sweep deletes temps of jobs not in the active set, with the age threshold (24 h default) as backstop only for job records that no longer exist — age alone would collect a long-running job's temps mid-write. (d) Writer materialization check: existing row + existing file → skip write; existing row + missing file → re-materialize; new row → temp, commit, rename.
